# Режим 11 «Занятие с ИИ»: голосовое занятие с языковой моделью

Добавлен 2026-11-03 (сборка 2026-11-03-11) как текстовый диалог по теме; 2026-11-04 (сборка
2026-11-04-1) переделан в голосовое занятие без выбора темы. Ученик говорит, микрофон слушает
постоянно, модель отвечает голосом и держится в рамках слов выбранного набора. Чем
заняться, ученик говорит сам по-русски в начале: поговорить на тему, поучить слова в разговоре,
отработать диалог, спросить про грамматику. Код: раздел «режим 11» в `index.html`
(`startDialog`, `dialogListen`, `dialogSend`, `dialogSpeak`, `renderDialog`, `aiRequest`).

## Голосовой цикл (с 2026-11-05, сборка 2026-11-05-10: кнопка «держи и говори»)

1. При входе приложение само (без запроса к API) показывает и озвучивает русским голосом
   приветствие `DIALOG_OPENER`: «Скажи по-русски, чем хочешь заняться…». Если русского голоса в
   системе нет, фраза только показывается.
2. Ученик нажимает и держит кнопку микрофона, говорит, отпускает — фраза уходит сразу, без
   ожидания тишины. Нажатие во время озвучки ответа её прерывает. Непрерывного прослушивания
   больше нет: оно давало 2–3 секунды задержки на определение конца фразы.
3. Что уходит модели, зависит от `aiAudioMode()`:
   - **`model` — запись голоса.** Пока кнопка нажата, `ScriptProcessor` копит сэмплы микрофона;
     при отпускании они усредняются до WAV 16 кГц моно 16 бит (`wavEncode`, около 32 КБ на
     секунду). С ключом OpenRouter и моделью с пометкой 🎤 (Gemini 3.8 Flash, Gemini 4 Argon,
     GPT Audio) звук уходит прямо в модель частью `input_audio` в chat/completions; схема ответа
     получает поле `heard` — дословно услышанное на языке речи, и после ответа запись в истории
     заменяется этим текстом, чтобы не слать звук повторно с каждым ходом. С ключом OpenAI запись
     сначала транскрибирует `gpt-transcribe` (`/v1/audio/transcriptions`, язык определяет сам;
     при 400/404 повтор с `gpt-4o-transcribe`), затем текст идёт обычным ходом в выбранную
     модель. Модель слышит речь, поэтому правило 8 системной подсказки просит отмечать явные
     ошибки произношения в `correction`. Claude звук не принимает: с ключом Anthropic режим
     `model` недоступен, переключатель в настройках погашен.
   - **`browser` — распознаёт браузер.** На время нажатия запускается Web Speech API на языке
     `session.lang`; латиница в промежуточном результате (греческий распознаватель так пишет
     русскую речь, на греческую латиницы не даёт, проверено) переключает на `ru-RU`, латинский
     обрывок уходит модели подсказкой о потерянном начале фразы. Отпускание — `stop()`, итог по
     `end`, страховочный таймер 2,5 с. Ручной переключатель языка остаётся.
   Выбор в настройках (`store.settings.aiAudio`): по умолчанию запись, если провайдер её
   принимает.
4. Ответ озвучивается по частям (`dialogSpeak`): греческие части греческим голосом, русские
   русским; затем кнопка ждёт следующего нажатия. По просьбе ученика модель переводит сказанное
   ею по-гречески (правило в системной подсказке), перевод приходит частью `ru`.
5. Кнопки: «Повторить запрос» при ошибке API (запись хранится до успешного ответа),
   🔊 у реплики модели (повторная озвучка), переключатель языка в режиме `browser`.
6. Метрики хода (с 2026-11-05-11) строкой под репликой модели: ожидание ответа, транскрипция
   (OpenAI), озвучка, длина и размер записи, токены, модель. Для OpenRouter в запросе
   `reasoning: {effort: "low"}` (Gemini по умолчанию «думает», это секунды задержки; при 400 с
   упоминанием reasoning повтор без него), `max_tokens`, а для моделей со словом audio в
   имени `modalities: ["text"]`.
7. Лексика (с 2026-11-05-12). Модели уходит вся основная лексика всех встроенных уроков
   (`dialogCourseWords()`, около 250 слов) как свободный словарь ученика, а слова выбранного
   набора — отдельной строкой как акцент занятия: вплетать, когда уместно, но не подгонять
   разговор под них (правило 2). Слова вне лексики курса — не больше двух за реплику с переводом
   в `new_words`. Подсветка «нет в наборе» тоже считает известной всю лексику курса.

## Где доступен

- Только при введённом ключе API в настройках (раздел «Диалог»). Без ключа режима нет в списке,
  на главном экране есть строка-подсказка.
- На iOS (с 2026-11-05-13) только с записью голоса в модель: ключ OpenAI или OpenRouter с
  моделью 🎤, переключатель «Распознаёт браузер» погашен; с ключом Anthropic режим на iPhone
  скрыт, потому что распознавание речи в браузере там не работает
  (`docs/ios-speech-recognition.md`). Режимы 9–10 на iPhone по тому же условию: запись попытки
  уходит модели (`sayAiCheck`, `aiSpeechCheck`), она возвращает услышанное, оценку и
  объяснение по-русски; услышанное сравнивается тем же `sayScore`. На остальных платформах это
  дополнительная кнопка «Отправить запись в ИИ» после локальной попытки (запись идёт
  параллельно браузерному распознаванию).
- В браузерах без Web Speech API (Firefox) режим скрыт даже с ключом, в настройках об этом
  предупреждение: ввод только голосом.

## Ключ, провайдер и модель

Принимаются три вида ключа API (с 2026-11-05, сборка 2026-11-05-3); провайдер определяется по
началу ключа в `aiProviderOf()`:

| Начало ключа | Провайдер | Куда идут запросы | Модели (первая — по умолчанию) |
|---|---|---|---|
| `sk-ant-` | Anthropic | `api.anthropic.com/v1/messages` | claude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5 |
| `sk-or-` | OpenRouter | `openrouter.ai/api/v1/chat/completions` | anthropic/claude-opus-5.5, anthropic/claude-sonnet-5.5, openai/gpt-6.1-sol, openai/gpt-6.1-terra, google/gemini-4-argon, google/gemini-3.8-flash |
| другое `sk-` (`sk-proj-`) | OpenAI | `api.openai.com/v1/chat/completions` | gpt-6.1-sol, gpt-6.1-terra, gpt-6-luna |

Ключ хранится в `store.settings.claudeKey` (localStorage этого браузера; имя поля историческое) и
уходит только к своему провайдеру. Ключ с другим началом не сохраняется, настройки объясняют, какие
принимаются. Это отдельные от подписок счета с предоплатой; на ключ стоит поставить месячный лимит
расходов. Кнопка «Проверить ключ» делает короткий запрос и показывает ответ модели.

Модель выбирается в настройках из списка провайдера (`AI_PROVIDERS` в `index.html`); первая в
списке — самая сильная модель провайдера, она и считается лучшей для греческого. Список OpenRouter
намеренно короткий: только модели Anthropic, OpenAI и Google, у которых греческий надёжен; идентификаторы
взяты из открытого списка `openrouter.ai/api/v1/models` 2026-11-05. Выбранная модель хранится в
`store.settings.claudeModel`; если она не из списка текущего провайдера, берётся первая.

## Запрос

Единая функция `aiRequest({system, messages, schema, maxTokens}, cb)` возвращает
`{text, stop, model, tokens}` независимо от провайдера.

Anthropic: `POST /v1/messages`, заголовки `x-api-key`, `anthropic-version: 2026-10-21`,
`anthropic-dangerous-direct-browser-access: true` (без него API отвергает запросы из браузера);
`system` с `cache_control`, `output_config.effort: "low"` и структурированный ответ
`output_config.format`. Для Opus и Sonnet добавляются `fallbacks: "default"` и заголовок
`anthropic-beta: server-side-fallback-2026-07-01`; если API вернёт 400 с упоминанием fallback,
запрос повторяется без них.

OpenAI и OpenRouter: `POST /v1/chat/completions`, заголовок `Authorization: Bearer`, системная
подсказка первым сообщением `role: system`, `max_completion_tokens`, структурированный ответ
`response_format: {type: "json_schema", json_schema: {name, strict: true, schema}}`. У OpenAI
передаётся `reasoning_effort: "low"`; если API отвергает параметр (400 с упоминанием reasoning),
запрос повторяется без него. OpenRouter получает ещё `HTTP-Referer` и `X-Title`. Оба сервиса
отвечают на CORS-preflight из браузера (проверено curl 2026-11-05 с Origin сайта).

Ответ разбирается `aiJson()`: как JSON целиком, а если модель обернула его в текст или ограду
` ``` `, по первой и последней фигурной скобке. Схема `DIALOG_SCHEMA`:

| Поле | Что |
|---|---|
| `parts` | реплика по частям `{lang: el|ru, text}`, каждая часть целиком на одном языке (озвучиваются разными голосами); основной язык греческий, по-русски коротко: подтвердить задание, объяснить, ответить на русский вопрос |
| `translation` | русский перевод греческих частей (показывается по кнопке «Перевод») |
| `new_words` | слова вне списка, не больше двух, с переводом |
| `correction`, `corrected` | объяснение ошибки ученика по-русски и его фраза в исправленном виде; пустые, если ошибок нет |
| `next_lang` | на каком языке модель ждёт ответ ученика: на него переключается распознаватель |

Системная подсказка говорит модели, что речь ученика распознана автоматически (возможны ошибки
распознавания, нет знаков препинания и ударений) и что ученика уже спросили, чем он хочет
заняться, так что его первая реплика — ответ на этот вопрос. В историю ответ модели кладётся
как есть (JSON-строка), чтобы она видела свой формат.

## Подсветка слов

`dialogKnown()` собирает известные ученику формы: слова набора, их множественное число и
спряжение из `grammar.js`, все слова предложений режимов 9–10 из `sentences.js` и список служебных
слов `DIALOG_COMMON`. В реплике модели слово вне этого списка подчёркивается пунктиром
(«нет в наборе»), объявленное моделью новое слово — синим пунктиром. Это проверка на нашей
стороне, независимая от того, что модель обещала.

## Ошибки

Ошибка запроса показывается под чатом, реплика ученика остаётся в истории, кнопка «Повторить
запрос» отправляет её снова. Отказ в доступе к микрофону, отсутствие сети или языка выключают
микрофон с пояснением. Занятие сохраняется в `sessionStorage` при перезагрузке на обновление;
после восстановления микрофон выключен, пока ученик не нажмёт «Слушать».

## Что не проверено

Весь поток проверен в Playwright с подменёнными распознавателем, озвучкой и ответом API
(скрипт в отчёте сеанса). С реальным ключом на 2026-11-04 режим не запускался: ответ модели,
качество удержания лексики, совместимость `fallbacks` со структурированным ответом, работа
непрерывного распознавания в реальном Chrome (длина сессии, разбиение длинных фраз) и
стоимость нужно проверить при первом запуске.
