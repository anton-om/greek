# Бэкенд: решения и аргументы

Решения владельца от 2026-11-05. Приложение остаётся статическим сайтом на GitHub Pages;
бэкенд, если появится, принимает и отдаёт только текстовые и числовые значения
(JSON небольшого размера). Никакого тяжёлого контента: звук, файлы и записи с микрофона на
сервер не отправляются.

## Что бэкенд должен дать

1. **Прогресс между устройствами.** Сейчас отметки «изучено» и настройки живут в `localStorage`:
   у Safari и у установленного приложения хранилище разное, у телефона и ноутбука тоже, чистка
   браузера всё стирает. Сервер с аккаунтом даёт один прогресс везде. Передаётся список слов и
   отметок, то есть текст.
2. **Статистика обучения.** Какие слова чаще всего не даются, сколько попыток уходит на фразу в
   режимах 9–10, на каком шаге люди бросают, какие уроки проходят до конца. Это данные для правки
   уроков и предложений. Передаются события с числами и ключами слов.
3. **Метрики лучше GoatCounter.** Сейчас видны только открытия, запуски режимов и завершения
   (`scripts/metrics.py`). Свой сбор событий даёт воронку по урокам, удержание по дням, время в
   режиме, срезы по платформам, без ограничений чужого сервиса.

## Что бэкенд делать не будет

- **Общий ключ API для режима 11.** Выбор стоит так: либо монетизация и общий ключ на сервере,
  либо ключи у каждого пользователя локально. Аудитории для монетизации нет, поэтому ключи
  остаются локальными (`docs/dialog-mode.md`).
- **Распознавание речи на сервере**, в том числе для iPhone. Отправка звука медленная, бьёт по
  отзывчивости, нагружает сервер и модель. Распознавание только браузерное
  (`docs/ios-speech-recognition.md`, `docs/native-app.md`).
- **Оценка произношения и выбор движка распознавания на сервере** — по той же причине: звук на
  сервер не уходит.

## Как это могло бы выглядеть

Небольшой JSON-API (например, Cloudflare Workers с KV или D1, бесплатный уровень): вход по коду
или аккаунту, `GET/PUT /progress` со списком изученных слов и настроек, `POST /events` с пачкой
событий. Приложение продолжает работать без сервера: при отсутствии связи прогресс остаётся
локальным и досылается позже.

## Работа без интернета

Service worker в приложении нет (на 2026-11-05). Открывается ли сайт без сети, зависит от
HTTP-кеша браузера, гарантии нет; установленное на iPhone приложение без сети обычно не
открывается. Проверка новой сборки при отсутствии связи молча пропускается. Из режимов интернет
нужен распознаванию речи (9, 10, 11) и запросам к модели (11); озвучка работает системными
голосами и без сети.
