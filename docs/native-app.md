# Идея: отдельное приложение

Сейчас приложение — PWA на GitHub Pages, на iPhone его ставят на экран «Домой». Ниже —
аргументы за отдельное (нативное или обёрнутое, например Capacitor) приложение. Пока не сделано.

## Аргументы

- **Распознавание речи на iPhone (режимы 9 и 10) — главный аргумент.** В PWA на экране «Домой»
  iOS не запоминает разрешение на микрофон и спрашивает его при каждом запуске. Web Speech API
  на iOS 27 работает только в первый раз после запуска (ноябрь 2026), обходы из кода не
  помогли, см. `docs/ios-speech-recognition.md`: ошибка воспроизводится и в обычном Safari,
  это ошибка WebKit. С 2026-11-03 на iOS вместо кнопки микрофона стоит поле с диктовкой через
  системную клавиатуру. Это работает, но как обход так себе: ученик переключает клавиатуру на
  греческую, нажимает 🎤 на клавиатуре, а не на экране приложения, и подтверждает ввод.
  Единственный способ вернуть на iPhone кнопку «держи и говори» — выйти из WebKit: в нативном
  приложении доступен системный распознаватель (`SFSpeechRecognizer`) с постоянным разрешением,
  а в обёртке (Capacitor) — тот же сайт плюс нативный плагин распознавания. Греческий
  распознаватель Apple поддерживает, но не на устройстве: на странице доступности функций
  iOS 27 греческий есть в списке «Dictation», но отсутствует в списке «Dictation: On-Device»
  (проверено 2026-11-03, https://www.apple.com/ios/feature-availability/). Значит звук
  пойдёт через серверы Apple — так же, как уже идёт при диктовке с клавиатуры, и как идёт
  через серверы Google в Chrome на Android. Для занятий это приемлемо, но офлайн режимы 9 и 10
  работать не будут.
- **Озвучка в беззвучном режиме.** Синтез речи в вебе глушится боковым переключателем iPhone,
  обходы не помогли. Нативное приложение само выбирает аудиосессию (`playback`).
- **Офлайн и хранение.** `localStorage` PWA iOS может очистить; в приложении данные надёжнее
  и проще синхронизировать с бэкендом (см. `docs/backend-ideas.md`).
- **Уведомления о повторении** (интервальное повторение) — в нативном приложении проще и
  надёжнее, чем web push в PWA.

## Против

- Публикация в App Store: аккаунт разработчика (99 $ в год), ревью каждой версии, обновления
  не мгновенные, в отличие от GitHub Pages.
- Вторая кодовая база или обёртка, которую надо поддерживать.

## Где ошибку распознавания можно обойти, а где нет

| Платформа | Кнопка микрофона (Web Speech API) | Вывод |
|---|---|---|
| iPhone, любой браузер (Safari, Chrome, Firefox) | Не работает: все браузеры на iOS обязаны использовать WebKit | Только диктовка через клавиатуру |
| iPhone, PWA на экране «Домой» | То же, плюс запрос микрофона при каждом запуске | То же |
| iPhone, мини-приложение Telegram | Telegram показывает мини-приложения в WKWebView — тот же WebKit. По WebKit bug 239816 Web Speech API включён только в Safari, во встроенных WKWebView `webkitSpeechRecognition` есть, но не работает | Не вариант: тот же движок, и распознавания там, вероятно, нет вовсе |
| iPhone, нативное приложение или обёртка с нативным плагином | Распознавание идёт мимо WebKit через `SFSpeechRecognizer` | Единственный путь вернуть кнопку на iPhone |
| Android, Chrome или Samsung Internet | Распознавание Google, ошибка WebKit не относится; нужен интернет | Кнопка работает (на устройстве пока не проверено) |
| Android, Firefox | Web Speech API нет | Поле ввода |
| Настольные Chrome, Edge, Safari | Работает | Кнопка |

Мини-приложение Telegram — это обычная веб-страница, которую клиент Telegram открывает во
встроенном WebView (на iPhone WKWebView, на Android Chrome WebView) и даёт ей небольшой JS-API
`Telegram.WebApp` (тема, кнопка «назад», данные пользователя, платежи). Движок страницы при
этом остаётся движком платформы, поэтому от проблем WebKit на iPhone Telegram не спасает,
а доступ к микрофону там ещё и ограничен сильнее, чем в Safari. Источники:
https://bugs.webkit.org/show_bug.cgi?id=239816, https://core.telegram.org/bots/webapps.

## Как устроена обёртка Capacitor

Capacitor (Ionic) собирает из обычного сайта приложение для iOS и Android: файлы `index.html`,
`words.js` и остальные кладутся внутрь приложения и открываются в системном WebView (на iPhone
WKWebView). Интерфейс и логика остаются теми же, что на GitHub Pages, вторая кодовая база не
нужна. Отличие от PWA — мост между JS и нативным кодом: плагины дают странице доступ к
системным API через обычные JS-вызовы. Для распознавания есть плагин
`@capacitor-community/speech-recognition`: на iOS он вызывает `SFSpeechRecognizer`, на Android —
системный `SpeechRecognizer`, странице отдаёт `start({language:'el-GR', partialResults:true})`,
событие `partialResults` с вариантами и `stop()`. Эти вызовы встают на место
`webkitSpeechRecognition` в `recBegin()`/`makeRec()`, а `sayEvaluate()` и подсветка не меняются.
В `Info.plist` нужны `NSSpeechRecognitionUsageDescription` и `NSMicrophoneUsageDescription`.

Что потребуется: Node и Xcode на Mac, `npm install @capacitor/core @capacitor/ios`, `npx cap add
ios`, затем открыть проект в Xcode. Поставить на свой iPhone можно бесплатным аккаунтом
разработчика (приложение живёт 7 дней, потом переустановка), для постоянной установки
и App Store нужен платный аккаунт. Обновления контента (слова, уроки) при этом перестают
быть мгновенными: нужна пересборка, если не грузить страницу с GitHub Pages по сети.
