# Идея: отдельное приложение

Сейчас приложение — PWA на GitHub Pages, на iPhone его ставят на экран «Домой». Ниже —
аргументы за отдельное (нативное или обёрнутое, например Capacitor) приложение. Пока не сделано.

## Аргументы

- **Распознавание речи на iPhone (режимы 9 и 10).** В PWA на экране «Домой» iOS не запоминает
  разрешение на микрофон и спрашивает его при каждом запуске. Web Speech API там работает
  нестабильно: на устройстве распознавание срабатывало только в первый раз после запуска
  (ноябрь 2026, сборка 2026-11-03-1). В нативном приложении доступен системный распознаватель
  (`SFSpeechRecognizer`) с постоянным разрешением. Подробности ошибки — в
  `docs/ios-speech-recognition.md`: она воспроизводится и в обычном Safari, это ошибка WebKit.
- **Озвучка в беззвучном режиме.** Синтез речи в вебе глушится боковым переключателем iPhone,
  обходы не помогли. Нативное приложение само выбирает аудиосессию (`playback`).
- **Офлайн и хранение.** `localStorage` PWA iOS может очистить; в приложении данные надёжнее
  и проще синхронизировать с бэкендом (см. `docs/backend-ideas.md`).
- **Уведомления о повторении** (интервальное повторение) — в нативном приложении проще и
  надёжнее, чем web push в PWA.

## Против

- Публикация в App Store: аккаунт разработчика (99 $ в год), ревью каждой версии, обновления
  не мгновенные, в отличие от GitHub Pages.
- Вторая кодовая база или обёртка, которую надо поддерживать.
